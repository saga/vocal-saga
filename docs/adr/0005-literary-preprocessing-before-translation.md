# ADR-0005：长篇文学翻译使用全书预处理，小范围选段允许轻量上下文

- 状态：Accepted
- 日期：2026-10-31
- 适用范围：Local Agent 文档项目中的文学模式（小说、散文、回忆录及其他文学类长文）
- 关联仓库：[vocal-saga](https://github.com/saga/vocal-saga)、[fanyi-extension](https://github.com/saga/fanyi-extension)
- 相关决策：[ADR-0001：统一本地翻译管线与初译上下文增量](0001-unified-local-translation-context-delta.md)、[ADR-0003：服务端项目权威与扩展离线副本](0003-server-authoritative-project-state.md)、[ADR-0004：全书文风基准采用分维度、可审阅的分析契约](0004-evidence-grounded-style-guide.md)

## 背景

长篇文学翻译的质量依赖跨章节人物、关系、实体、叙述风格和章节上下文，因此全书范围任务仍应复用同一份全书预处理快照。另一方面，用户经常只翻译少量选段、当前页或一段对白；强迫这些小任务等待一次全书分析，会增加不必要的等待和模型调用，并不总能带来相称的质量收益。小范围任务可以在明确边界内使用片段级上下文，但不能放宽原文版本、规范译名、证据和译文完整性约束。

Local Agent 已经拥有服务端 SQLite Context Graph、可恢复的预处理工作流和按批次构建的 TranslationBrief。问题不应通过扩展复制图谱或另建一套分析系统解决。

## 决策

1. **长范围文学翻译先完成全书预处理。** 全书/大范围任务在当前 source revision 的 Context Graph 完成并通过 readiness 检查后才开始翻译。小范围选段（最多 12 个有效片段且源文总计不超过 6,000 字符）在没有可用全书图谱、且没有正在运行的全书分析时，可以跳过等待，使用当前片段、前文和已确认记忆；已有分析正在运行时仍等待其完成。技术文档模式不受此门禁影响。
2. **预处理结果必须属于本次翻译的准确输入版本。** readiness 必须同时匹配 sourceRevisionId、服务端当前 CONTEXT_GRAPH_ANALYSIS_VERSION、sourceLang 和 targetLang；不能把旧原文版本、旧分析版本或其他语言方向的结果用于当前 Run。
3. **完成状态不是单独的充分条件，但风格报告不设字段齐全门槛。** readiness 要求受支持的工作流策略（A 或 B）、大于零的有效分析样本，以及 B 工作流的 style、characters、entities、relationships、chapters 必要阶段检查点。五项文风描述（叙述声音、语域、节奏与句法、对白特征、措辞与词汇）、styleRules 和 styleAvoid 是模型尽力提取的参考资料，不是翻译准入条件；缺少某项只表示该维度没有可靠资料，不得阻止翻译或要求模型编造补齐。
4. **区分预处理完整性与用户确认。** styleGuideReady 表示服务端分析契约完整，不代表用户已经确认文风。符合版本和完整性要求的机器文风基准可按现有策略自动应用；明确的用户编辑/确认具有更高优先级。自动应用不得伪装成用户确认。中文 Literary Editorial Profile 仍遵循独立的来源版本与证据追溯约束，但通过校验后默认以 `model-default` 应用；用户可以事后编辑或拒绝，不需要确认步骤，也不影响主翻译 Run。
5. **扩展负责 UI 状态，服务端负责最终执行门禁。** 扩展从轻量 /context-graph/status 投影读取状态；长范围任务必须满足来源、版本、语言和阶段检查。小范围选段的轻量分流由服务端根据 Run 实际片段数和源文长度判定，客户端不得自行伪造 readiness。扩展不下载或复制图谱节点、证据和章节摘要。
6. **服务端门禁不可绕过。** executeRun 在 Run 进入 running、读取待翻译片段和调用翻译模型之前再次验证。旧版客户端或直接 API 调用可能先持久化一个 queued Run；服务端可以自动启动/等待匹配的 Context Graph，但在 readiness 通过前绝不进入翻译阶段或写入译文候选。Run 创建本身不等于翻译已经开始。
7. **预处理首次启动与失败恢复采用不同策略。** 对从未分析过的当前来源版本，扩展在建立项目后自动触发一次预处理并展示进度。用户明确点击“开始翻译”时，该操作同时授权系统对失败、过期、版本/语言不匹配或完整性不足的分析执行一次有界重分析，并自动等待结果；不进行无限重试。若这一次重分析仍失败，显示明确诊断，用户可在“人物与预处理”手动重新分析。服务端对直接 API Run 保留最终门禁和明确失败诊断。
8. **长范围预处理失败必须 fail closed，小范围有界降级。** 不允许把长篇全书预处理失败转换成警告后继续整本翻译。只有明确符合小范围阈值、Run 仍绑定项目当前原文版本、且没有正在运行的全书分析时，才允许使用片段级上下文继续；不得把该例外扩展到全书/大范围任务。
9. **保留可恢复性和历史。** 预处理 run、检查点、失败原因和事件保存在服务端项目 SQLite。重分析不能改写旧 Run 固定的 source/memory/TranslationBrief 快照，也不能覆盖已采纳译文或人工修订。

## 职责边界

- local-agent-service：Context Graph 运行、持久化、证据校验、readiness 计算、直接 API Run 的最终门禁、失败诊断和事件轨迹。
- fanyi-extension：新项目首次预处理触发、轻量状态轮询、用户显式重分析入口、文学 Run 的 UI readiness gate，以及翻译进度展示；不持有图谱事实、不实现第二套分析算法。
- 技术文档翻译：继续使用统一 Project/Run executor，但不要求 Context Graph 文学预处理。

## 后果

- 新文学翻译不会在缺少全书上下文时提前开始；预处理失败会明确阻止，而不是悄悄降低质量。
- 正常扩展路径只需一次明确的开始翻译动作：必要预处理自动衔接，readiness 通过后自动开始全书待译片段；不要求逐页/逐章重复点击。
- 服务端仍能保护绕过扩展的调用方；此类调用可能产生 queued Run 记录，但不会提前调用翻译模型。
- 预处理会增加首次翻译前的等待时间，这是质量优先的明确取舍。
- 不引入第二份 Context Graph、扩展端全书记忆副本或新的并行 Agent 流水线。

## 验收标准

1. 当前原文版本、分析版本或语言方向不匹配时，文学 Run 不调用翻译模型；单纯缺少某个文风字段或 style rule 不得阻断 Run。
2. 状态未知、预处理 queued/running/failed 或完整性不足时，不调用文学翻译模型；用户发起的同一次操作可以自动启动/等待一次预处理，ready 后再创建 Run。
3. B 策略缺少任一必需阶段时，服务端和扩展都拒绝 readiness。
4. 直接调用 Run API 时，服务端可持久化 queued Run，但在 Context Graph ready 前不得将 Run 设为 running、调用翻译模型或保存候选。
5. 预处理失败不会退化为逐章分析后继续文学翻译；一次自动重分析仍失败时，本次请求明确结束，不要求用户再点开始来触发正常续接。
6. 技术模式不被 Context Graph 门禁阻断。
7. 既有 accepted translation、人工修订和旧 Run 快照在重新分析后保持不变。

## 当前统一规则：默认采纳、事后纠正（2026-10-31，优先于本文旧描述）

- 模型产生的当前最佳结果在通过来源/结构完整性校验后默认参与后续翻译；不得要求用户逐项确认人物、实体、关系、声音、文风或普通审校发现。
- `model-default` 是机器默认采纳，不是用户确认。用户修改、确认和拒绝必须分别记录；`user-modified` 与 `user-confirmed` 均优先于机器默认结果。
- 用户拒绝/删除必须持久化，重新分析、记忆刷新、TranslationBrief 合并不得自动恢复。不得仅删除 UI 或 LiteraryMemory 投影而让 Context Graph 原记录继续注入。
- 证据不完整只影响置信度、可用范围和约束强度，不得仅因文风字段、画像维度、关系证据覆盖不完整而阻断翻译。
- 保留原文版本、语言方向、来源绑定、未来章节隔离、译文写回位置和数据完整性等硬约束。只有缺少不可替代输入、数据损坏或执行无法继续等技术异常才暂停。
- 自动应用必须保留来源与版本记录，且不得覆盖用户修改；用户可以事后修改或拒绝。
- 任何旧段落中要求“候选必须人工确认”“证据完整后才能启用”“风格字段必须齐全”的规则均已被本节取代。
