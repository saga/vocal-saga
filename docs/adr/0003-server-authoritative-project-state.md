# ADR-0003: Local Agent 项目数据唯一服务端持久化

- 状态：Accepted
- 日期：2026-10-31
- 相关项目：[fanyi-extension](https://github.com/saga/fanyi-extension)
- 相关决策：[ADR-0001：统一本地翻译管线与初译上下文增量](0001-unified-local-translation-context-delta.md)、[ADR-0002：本地翻译全流程审计账本与原始来源保全](0002-local-translation-audit-ledger-and-source-preservation.md)

## 背景

历史实现曾将同一份文档、译文和 LiteraryMemory 同时保存在 Local Agent SQLite 与浏览器扩展 IndexedDB。即使服务端被定义为权威来源，扩展仍保留离线快照、双写和本地恢复路径，增加了状态分叉与同步复杂度。目标架构明确为：Local Agent 服务是文档业务数据唯一持久化边界；扩展只负责 UI、浏览器文件交互和当前页面内存投影。

## 决策

### 1. 已存在项目的权威数据源是 Local Agent 服务

当服务可用且当前文档可以关联到服务端项目时，服务端项目库是以下信息的唯一权威来源：

- 当前原文版本、分段及其指纹；
- 已采纳译文、人工修订、候选译文与审校结果；
- Prompt 版本、翻译策略、文学记忆与 Context Graph；
- Run 状态、运行历史、事件轨迹及质量审计记录。

Context Graph、原文证据、章节摘要和全书分析产物只在 Local Agent 的项目 SQLite 中保存和检索。扩展不得把图谱节点/证据批量合并进 LiteraryMemory，也不得在轮询状态时下载完整图谱。扩展只读取用于 UI 和文学翻译前置检查的小型状态投影；它不持有图谱事实或分析算法。文学翻译的正常扩展路径必须先确认当前来源版本的预处理 ready，再创建翻译 Run；服务端 executeRun 仍执行最终门禁。旧客户端或直接 API 调用即使先创建了 queued Run，服务端也必须自动启动/等待匹配的预处理，并在 ready 前禁止进入 running、调用翻译模型或写入译文候选。详细门禁见 [ADR-0005](0005-literary-preprocessing-before-translation.md)。

扩展 UI 在打开文档、恢复会话、刷新页面以及进入 Agent Workspace 时，必须重新查询服务端项目并刷新当前页面内存投影。Local Agent 模式下扩展不得持久化文档、译文、LiteraryMemory 或 Context Graph 到 IndexedDB、localStorage 或扩展 storage；这些数据只能保存在服务端项目数据库。

### 2. 项目发现不能只依赖扩展本地映射

扩展本地 project ID 映射是加速索引，不是项目存在性的依据。服务必须提供基于当前文档来源指纹的解析接口：

- 指纹精确匹配：关联该项目，并从服务端重新读取当前状态；
- 文件身份或标题相同但原文指纹不同：仅作为来源可能变化的候选，不能把旧译文直接套用到新原文；应保留历史并要求显式登记新来源版本或另建项目；
- 无匹配项目：只有在用户启用 Local Agent、需要使用服务端项目时才创建新项目；
- 服务不可达、鉴权失败或请求超时：不能将其误判为项目不存在，也不能因此自动新建重复项目或覆盖本地/服务端记录。

关联成功后，扩展可以刷新本地 project ID 映射，以便下次快速发现同一项目。

### 3. 禁止在打开/恢复时将扩展快照回灌到已有服务端项目

已有服务端项目必须以只读同步为默认路径。扩展不得在打开文档、恢复会话或普通 Run 创建时，把本地缓存的译文、Prompt 或文学记忆无条件提交到已有项目。遗留数据迁移只能发生在显式创建的新项目、明确的用户迁移操作或其他被单独审计的写入流程中。

所有影响项目状态的写操作都应经由明确的用户动作或服务端项目工作流完成；本地记录落后时，先从服务端刷新，而不是以“补齐”为由覆盖服务端数据。

### 4. EPUB/PDF 原始文件导入必须由 Local Agent 负责

当 Local Agent 已启用时，EPUB/PDF 应把原始文件字节通过 `POST /api/documents/projects/import-file` 交给本机服务。服务负责文件校验、文本/章节解析、稳定片段生成和原始文件/片段持久化。扩展只能加载分页后的结构化片段用于阅读器渲染，不得把整本书解析成一个 JSON 请求发送到项目创建/解析接口。扩展内的 PDF.js/JSZip 解析器只保留给未启用 Local Agent 的离线或轻量路径；解析结果不能取代服务端项目的来源事实。

原文件来源变更同样走服务端：通过二进制上传触发 `source-file` 的来源版本更新操作。若同名项目存在不同原文，服务端返回冲突信息；扩展必须要求用户明确更新来源或另建项目，不得把旧译文直接套到新版本。字节完全相同的原文件应优先复用既有项目，避免重复解析及重复项目。

原始文件大小是本机服务的配置边界，不应借用 JSON 请求体限制来限制整本书。默认上限为 512 MiB，可通过 `LOCAL_AGENT_MAX_DOCUMENT_SOURCE_MB` 调整；解压/文本展开上限由 `LOCAL_AGENT_MAX_DOCUMENT_EXPANDED_MB` 控制，PDF 文本提取超时由 `LOCAL_AGENT_PDF_TIMEOUT_MS` 控制。服务仍需保留合理的资源上限和解压炸弹防护，而不是无条件接受无限大小文件。

### 5. 阅读器恢复记录不重复保存项目正文

通用 `document_sessions` 只保存 `projectId`、阅读位置、语言、视图和当前 Tab 等轻量恢复元数据。原文片段、原始文件、已采纳译文、文学记忆、Prompt、Run 和审校记录只保存在项目数据库，不得复制到 reader-session。恢复时根据项目 ID 从服务端读取项目与文学记忆，并分页读取片段/已采纳译文。扩展 IndexedDB 不再作为 Local Agent 文档的主存储、离线副本或恢复来源；旧版全量会话只能在服务端项目成功恢复后清理，不得自动回灌已有项目。

### 6. 文学记忆大小限制只应用于规范化 DTO

`LiteraryMemory` 接口应先投影已知字段并清理为规范结构，再计算持久化大小。来源全文、Context Graph、原文证据全集等不得作为未知字段嵌套进去。超出预算时按稳定优先级裁剪低价值示例/摘要/锚点和多余证据，并显式标记证据截断；不得裁切 JSON 字符串，也不得把 120 KiB 作为整本书分析的数据上限。

### 7. 离线恢复不等于事实来源切换

当 Local Agent 服务不可用时，扩展不得将 IndexedDB 或其他浏览器存储中的旧业务数据作为离线副本恢复，也不得将未提交的 UI 草稿显示为已保存。应明确提示服务不可用；当前页面内存状态不保证持久化。服务恢复后重新从 Server 读取项目。扩展可保留不含业务内容的 project ID 定位映射，但映射不是项目事实来源。

## 后果

- Local Agent EPUB/PDF 流程传输原始二进制，不再把整本书装进 JSON；阅读器会话只存项目引用，减少重复存储和恢复负担。
- JSON API 的体积上限不再被误用作源文件限制；原始文件/展开后文本仍有配置化资源边界。

- 清理浏览器存储或刷新页面不会丢失服务端项目数据；扩展映射丢失时仍可从服务端发现匹配项目。
- 同一文档在阅读页、Agent Workspace 和恢复流程中看到一致的译文、运行和记忆状态。
- 必须增加项目解析 API 及服务端/扩展回归测试；同步不能被实现成每次打开时的双向覆盖。
- Local Agent 模式不再存在扩展端业务数据副本；减少双写、冲突解决和过期快照恢复路径。
