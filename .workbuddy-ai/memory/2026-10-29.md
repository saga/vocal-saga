# 2026-10-29

## Context Graph 预处理：修 NOT NULL 崩溃 + 并行波次

### 崩溃根因（run 85834967，Project Hail Mary）

- `contextGraph.ts` 的 `applyAnalysis` 里重置上一轮模型章节摘要时写 `SET summary = NULL`，
  但 `context_graph_chapters.summary/summary_kind` 是 `NOT NULL` 列。
- 后果：同一 source revision 的**第二次**预处理必挂。第一次（10-27 strategy B）写入 22 条
  `summary_kind='model'`，第二次（strategy A）在模型跑完 240s、输出 42,456 token 之后抛
  `NOT NULL constraint failed`，整轮被事务回滚。
- 修复：抽出 `resetChapterSummariesForReanalysis(db, revisionId, segments)`，改成
  `summary='' / summary_kind='extractive'` 再调 `writeChapterSnapshots` 重算确定性摘要。
  回归测试在 `tests/document-context-graph.test.mjs`。

### 并行波次

- `contextGraphWorkflow.ts` 新增 `CONTEXT_GRAPH_STAGE_WAVES = [[style,characters,entities],[relationships,chapters]]`
  和 `CONTEXT_GRAPH_STAGE_SESSION_PARENT`（chapters→style、relationships→characters）。
- `contextGraph.ts` 的 B 策略改成 `runStage()` + 波次 `Promise.all`；Session key 改成
  `contextGraphSession:<runId>:<stage>`，style 沿用旧的无后缀 key（文风补全路径依赖它）。
- 阶段检查点/进度写库全是同步操作，读改写之间没有 await，所以并发不会丢 `completedStages`。

### 实测（run c4ef2453，同一本书 6196 段）

| 阶段 | 串行(10-27) | 并行(10-29) |
|---|---|---|
| style | 55.8s | 49.4s |
| characters | 38.5s | 83.6s |
| entities | 43.7s | 76.1s |
| relationships | 35.4s | 71.5s |
| chapters | 45.0s | 85.9s |
| **总计** | **218.4s** | **169.9s** |

- 只有 1.28x：并发把单次调用延迟抬高约 1.9x（同一个模型端点争用），不是调度问题。
  想再快只能降 `contextGraph` 的 `effort: high`（`taskProfiles.ts:72`）或减输出量。
- 输出质量没退化：characters 6、entities 5（模型给 9，策略过滤掉国名/语言名）、
  relationships 16、chapterSummaries 22、openQuestions 13、evidence 59。

### 策略默认值

- `chooseContextGraphStrategy` 不再 A/B 交替：默认恒为 B（有检查点、有阶段进度、快 1.28x），
  A 只能通过 `LOCAL_AGENT_CONTEXT_GRAPH_STRATEGY=a` 显式启用。
- `contextGraph.ts:1718` 的 env 默认值同步从 `'ab'` 改成 `'b'`。
