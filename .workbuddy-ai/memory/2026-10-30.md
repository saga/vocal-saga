## 预处理「没有记录」误报（跨仓库修复）

**现象**：阅读页提示卡同时出现「当前原文版本尚无可用的全书预处理记录」和
「预处理任务 4a2a7085… · 全书预处理完成」。用户无法判断到底完成没有。

**结论：预处理确实完成了。** run 4a2a7085（Proust 全七卷，7366 段）10:09:13→10:17:41，
status=completed，5 步全过，revision `78bad929` 与当前一致，产出 36 人物 / 20 实体 /
57 关系 / 43 章节 / 55 条规范译名 / 195 条证据，`analysisVersion = context-graph-v9-…`。

**两个 bug**：
1. `fanyi-extension/.../documentPreprocessing.ts` 硬编码
   `CONTEXT_GRAPH_ANALYSIS_VERSION = 'context-graph-v7-…'`，服务端已 v9 →
   readiness 永远 `reason: 'version'`。`documentPreprocessing.test.ts` 还断言了这个 v7 常量，
   把漂移锁死。
2. `App.vue` 的 banner 标题三元只判了 queued/running/failed/language，其余 reason
   全落到「尚无可用的全书预处理记录」，与下方 runId + 「全书预处理完成」自相矛盾。

**修复（服务端权威）**：
- `contextGraph.ts` status DTO 增加 `currentAnalysisVersion`（服务端当前版本），
  与 `analysisVersion`（该记录产出时的版本）区分。
- 扩展删除本地版本常量，改比 `progress.analysisVersion !== snapshot.currentAnalysisVersion`；
  服务端没下发版本时**不做判断**（显示投影不猜版本，真门禁在 `translationAgent.ts:1383`）。
- 新增纯函数 `preprocessingGateTitle(reason)`，每个 reason 独立文案；`version` 与
  `missing` 不再共用一句。
- 测试：扩展 19 项（含「服务端未下发版本不误报」「每个 reason 文案唯一」），
  服务端 254 项全过；`vue-tsc`/`tsc --noEmit` 无新增错误。
- 实测线上 status 返回 `analysisVersion == currentAnalysisVersion == v9` → 就绪，banner 消失。

- **effort 在这条 pipeline 里没有 medium**：`deepseek-v4.1-flash` / `glm-5.3-flash` 都只声明
  `supportedEfforts: ["low","high","max"]`，SDK `clampEffortToSupported` 按「≤ 原值的最高档」

## 「翻译 Agent」面板空状态重做

**现象**：用户没开始翻译，面板却显示「等待继续 / 继续完成这份文档 / 0% / 7,366 段待处理 /
自动保存失败 + 重试保存 / 失败 · 服务重启中断了这次运行」。

**根因（三条，都在扩展侧）**：
1. `acceptedSegmentCount === 0` 与「已翻一部分」共用一句「继续完成」，首次打开就被告知在续做。
2. 打开面板取 `runs[0]`，而 `runs[0]` 是被服务重启打断的**自动质量修复子 Run**（failed，
   78 candidate + 22 pending），于是顶部直接显示「失败」。
3. 该子 Run 仍带 pending 片段，`autoAcceptReadyCandidates()` 调用服务端结算被
   `projectStore.ts:2315` 以 409 拒绝（「拒绝结束采纳事务」），原始内部措辞原样贴到界面上，
   而且 `error` 和 `autoAcceptError` 同时赋值 → 同一句话出现两次。

**修复**：新增 `documentAgentPresentation.ts`（纯函数 + 10 项测试）：
`agentProgressCopy` 三态（idle / running / resuming / complete）、`canAutoAcceptRun`
（只有 awaiting_acceptance / partial / completed 才允许结算）、`pickInitialRun`
（优先 live，其次最近一次人工 Run）、`humanizeAgentError`（内部措辞 → 人话）。
组件侧：删掉 hero 的空话与 kicker、未开始不画 0% 和空进度条、预处理提示复用
`preprocessingGateTitle` 且阶段名走父组件中文 `phaseLabel`、自动保存失败不再写全局 error。

**已知但未改**：服务端 `acceptRun` 对 failed 且带 pending 的 Run 仍会 409，正确动作是
「恢复运行」而不是结算；UI 现在不会再把这条 409 当成「保存失败」推到用户面前。

**注意**：该 failed 子 Run 是 20:40 我改 `contextGraph.ts` 触发 tsx watch 重启时打断的。
改服务代码前先确认没有在跑的 Run。

## 「全书文风基准」其实一直自动生效，按钮是摆设

**结论**：机器文风基准默认就注入，不需要确认。

证据（Proust 项目 `translation_briefs`）：每一批的
`contextGraph.styleGuide.sourceStatus = 'machine-applied'`，7 个字段
（narrativeStyle/register/rhythm/dialogue/diction/rules/avoid）全部在。
链路：`translationBrief.ts:984-1004` 用 context graph 的 styleGuide 组装，
`contextGraph` 整个对象 JSON 进 prompt（`translationAgent.ts:807`）。

**两条通道别混**：
- `brief.contextGraph.styleGuide` ← 机器基准，`styleGuideAutoDisabled !== true` 即自动注入。
- `brief.voiceContext.styleGuide` ← 只在 `styleGuideStatus === 'confirmed'` 时非空
  （`voiceContext.ts:586`），而所有项目的 status 都是 `candidate` → 这条通道实际是空的。

**「确认并注入后续翻译」按钮是纯装饰**：它只把 sourceStatus 从 `machine-applied` /
`user-edited` 改成 `user-confirmed`，注入内容一模一样。更糟的是它有反作用：
`setStyleGuideStatus('confirmed')` 会让 brief 走 `userStyle` 分支，如果
`literaryMemory.styleGuide` 是空的（没先导入），就会把机器基准整块覆盖成空字段。

**修复**：删除「确认并注入后续翻译」「撤销确认」两个按钮与
`setStyleGuideStatus` / `hasStyleGuideContent`；徽章改由纯函数
`styleGuideBadge()` 输出（已自动应用 / 你的编辑已生效 / 机器基准已停用 / 预处理未就绪），
3 项测试覆盖。用户编辑仍走 `styleGuideOrigin='user-edited'` 自动生效。

**教训**：徽章文案与按钮必须和真实注入路径对齐；「已自动应用」旁边摆一个「确认」按钮，
用户只会理解为「其实没生效」。

## 非英文原文支持审计（报告：non-english-support-audit.md）

翻译本体不受影响（原文整段直送模型，`translationAgent.ts:813` 显式传 sourceLang/targetLang）。
失效的是预处理启发式索引和确定性审计，全部只有 en(+zh) 规则：

- **P0 数字审计 100% 误报**：`numericTokens` / `numericQuantityUnits` 只认英文数词，
  非英文源侧恒为空 → 任何"数字+单位"的正确译文都被判 `numeric-token-mismatch`。
  实测 fr/de/it/ja 全 flag=true，en=false。不触发自动返工（自动返工只处理 missing-translation），
  但污染报告、误导人工返工。修法要点：**识别不到 ≠ 不一致，应跳过**。
- **P1 名称候选失效**：`NAME_PATTERN` 的 `\b` 基于 ASCII `\w` → `Émile`（出现 4 次）零 mention；
  日文零 mention（无大小写无 `\b`）；德语因名词全大写 → `Mann(2)`/`Stadt(2)` 成人物候选。
  连带 prompt 的"覆盖完整性检查"在候选为空时形同不存在。
- **P1 对白识别失效**：`quoteSpans`/`quoteCount` 无 `«»`、无 `„"`，`SPEECH_VERBS` 只有英文
  → fr/de/it 对白段 0/3（ja 1/3 靠「」）。对白抽样为空 → voice 描述退化。
- **P2 残留检测只认英文**：`[A-Za-z]` 词表；`déjà`/`schön` 被切成单字母碎片不可见；
  日文残留结构上不可检测。
- 低优先级：`contextGraph.ts:1505` 冠词归一化只处理 `the/a/an`。

## 扩展「无法连接本机服务」残留错误（已修）

现象：服务已恢复，阅读页仍显示「读取 workspace 运行状态失败：无法连接本机服务…」。

根因：轮询确实存在（App.vue `followWorkspaceRun` 900ms，Agent 面板 1200ms），
但**一次 `Failed to fetch` 就让整条轮询链终止**，catch 写一条 error 后没有任何东西会再清它。
`tsx watch` 改文件必然重启 → 正好制造这一次失败。所以错误是**残留**，不是当前状态。
`useAgentTrajectory` 那条是唯一无条件重排的，所以轨迹 Tab 会自愈。

修复（fanyi-extension）：
- `documentWorkspaceClient.ts` 新增 `isServiceUnreachableError()` = `WorkspaceApiError.status === 0`
  （`workspaceApi` 已把传输层失败收敛成 status 0，不要靠文案匹配）。
- App.vue：`workspaceApiWithReconnect()` 在 status=0 时重试（20×3s），阶段文案显示"正在重连"；
  `reportWorkspaceConnectionFailure()` + 有界重探（60×3s，打 `GET /api/documents/projects`）
  在服务恢复后**自动清掉残留错误**；catch 增加 generation 守卫，避免"主动停止"被显示成失败。
- DocumentAgentWorkspace.vue `schedulePoll`：status=0 时重新排程（20 次），成功后清掉连接类 error。
- useContextGraph.ts `refreshContextGraphStatus`：status=0 时重新排程（20 次），成功重置计数。
- 新增 `src/__tests__/serviceUnreachable.test.ts`（3 例）。全量 644 测试通过，无新增 tsc 错误。

### 补充：真正的根因是「错误被持久化」（上一轮只修了症状）

硬证据：`~/.vocal-saga-local-agent/local-agent.sqlite` 的 `document_sessions.snapshot.error`
里存着完整的「读取 workspace 运行状态失败：无法连接本机服务…」；
而同一秒（07:08:00–01）日志里 `POST /api/documents/session/save → 200`。
**显示"连不上"的同时还在成功写会话** —— 错误是假的、且是历史残留。

自循环链条：
1. 06:57:18 服务收到 SIGINT 退出，正在跟的 run 断掉 → 一次 `Failed to fetch`
2. 写进 `state.value.error`
3. `getSnapshot()`（useDocumentTranslation.ts:674）把 `state.error` 一起快照
4. `persistDocumentCheckpointToLocalService` 存进 SQLite（App.vue ~1877）
5. `restoreLastSession` → `restoreSnapshot({ error: saved.error })` 每次打开都恢复
6. 恢复出来的 error 又被下一次 save 写回去 → 永不消失，刷新页面无效

修复：`isServiceConnectivityMessage()`（documentWorkspaceClient.ts）+
写入侧过滤（snapshot.error）+ 两处 restoreSnapshot 调用点过滤（连历史脏数据一起清）。
注意 `getSnapshot`/`restoreSnapshot` 在 useDocumentTranslation.ts，**两处 restoreSnapshot 调用都在 App.vue**（~2201、~2458）。
已 `npx wxt build` 重新构建 `output/chrome-mv3`（注意构建目录是 `output/` 不是 `.output/`）。
