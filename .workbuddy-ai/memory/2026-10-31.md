## 轮询日志噪音（已修）

实测 `~/.vocal-saga-local-agent/logs/local-agent.log`：7934 行 / 815KB，
`[http]` 占 59%，其中 `GET .../context-graph/status → 200` **2196 行（27%）**。

根因：`src/server.ts` 里静默规则写成 `/\/context-graph$/`，只匹配裸路径；
扩展实际请求 `/context-graph/status`，**永远不命中**，注释里写的「轮询静默」形同不存在。

修复：
- `src/log.ts` 新增 `isPollingRequest`（正则 `/\/context-graph(\/.*)?$/`，覆盖子路径）、
  `collapsePath`（UUID→:id）、`PollingRollup` + `formatPollingSummary`。
- `src/server.ts` 静默改为累计，每 60s 打一行
  `轮询汇总 · 最近 42s 静默 6 次（... ×6 · 最慢 9ms）`；`server.on('close')` 补最后一行并 clearInterval。
  出错 / 慢请求(≥3s) / 写操作仍逐条输出。
- 实测验证：连打 6 次 status → 0 条明细 + 1 条汇总。
- `tests/request-log.test.mjs`（6 例），全量 290 测试通过，tsc 干净。

顺带：`npm test` 之前把测试日志写进**生产日志文件**（`listening on` 43 次、`json-repair salvaged` 44 次）。
已在 package.json 的 test 脚本里把 `LOCAL_AGENT_LOG_FILE` 指到 `${TMPDIR}`。

## 打开文档自动开始预处理（fanyi-extension）

原先预处理只在「开始翻译」时由服务端 `ensureLiteraryPreprocessingBeforeRun` 自动拉起
（`translationAgent.ts:1429`，最多 2 次尝试）。打开文档只读状态，用户必须先点按钮。

改动：
- `documentPreprocessing.ts` 新增纯函数 `shouldAutoStartPreprocessing({required,status,segmentCount,analyzing,alreadyAttempted})`：
  只对 `status === 'not-started'` 且 segmentCount>0 且 literary 且本地 Agent 生效。
  **failed / 版本过旧不自动重跑**（前者可能是配置问题会连续烧全书分析，后者是成本决策）。
- `useContextGraph.ts`：`refreshContextGraphStatus` 成功后 `void maybeAutoStartPreprocessing(project)`；
  `autoStartAttempted: Set<'projectId:revisionId'>` 先登记再发请求，防止 409（正在翻译）后
  每 1.2s 轮询重试一次 POST。`resetContextGraph` 清空。
- `ensureContextGraphPreprocessing(project, { auto })`：自动失败文案为「全书预处理未能自动开始：…」。
- 覆盖的入口：打开/恢复项目（App.vue:3197、2865）、切到文学模式（watch 的 index 2 = effectiveDocumentTranslationMode）、
  Agent 工作区（同一个 App.vue 子组件，共用 composable）。
- 测试：`documentPreprocessing.test.ts` +4 例；`serverAuthoritativeProjectState.test.ts` 里
  原来那条「opening 时不得启动预处理」的断言改写成「只经 composable 启动且仅限 never-analysed」。
  全量 652 通过，wxt build 已更新 output/chrome-mv3。
- 顺带改文案：App.vue 里「点击开始文学翻译后…」改成「全书预处理在本机服务里跑…」（自动启动后原句已不准）。
