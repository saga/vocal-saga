## 清空 vue-tsc 既存错误 + CI 必过门禁（fanyi-extension）

- 起点：`npm run compile` 有 304 个 TS 错误，分布在 80+ 文件（TS2532/18048 空值、
  TS2345 参数类型、TS2304 未声明全局等）。`npm run build`（WXT/Vite/esbuild）只转译不检查类型，
  所以漏导入 `shouldUseLightweightLiterarySelection` 一路通过 build。
- 第一步：`tsconfig.json` 的 `include` 补上 `.wxt/wxt.d.ts`（原先只 include src，导致 WXT
  自动导入的 `defineBackground` / `browser` 全部 TS2304），304 → 289。
- 余下 289 个按 5 个互不重叠的文件组并行修复（2 组测试、utils、runtime entrypoints、document），
  最后手工修掉 `translateApi.test.ts:201` 一处 mock.calls[0]。总体不改运行时行为：
  空值用 guard / `?.` / 在既有断言后的 `!`，修正 import 与类型形状，去掉可证明不可达的分支。
- 值得注意的行为等价调整：`sessionStore.ts` 的空文学记忆从 v1 字面量改为
  `createEmptyLiteraryMemory()`（v2），读取端本来就会 sanitize；`translateBatchText` 取消运行的
  返回值由 `false` 改为空 `Map`（与声明返回类型一致，调用方一直当 Map 用）。
- 结果：`npm run compile` **0 错误**（exit 0，使用本地缓存 pnpm 10.24.0 也验证通过）；
  `npm test` 71 文件 / 686 项通过；Chrome + Firefox 构建通过。
- CI：`.github/workflows/ci.yml` 在 `pnpm install` 与跨项目检查之后、单测之前新增
  `Type check: pnpm compile`，与 tests/两个 build 同属 `validate` job（push/PR 都跑）。
  GitHub 分支保护里把 `CI / validate` 设为必需检查才会真正阻断合并。
