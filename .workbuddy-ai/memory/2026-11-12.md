# 2026-11-12

## 修复：远端整页译文缓存漏查 DB999（Cloud Worker 链路）

**根因**：`lib/translate/pageStore.ts` 的 `createD1FailoverDatabase().first()` 只在「主库完全无行」时才查备用库；而 `/fanyi/page/check`、`POST /fanyi/page` 的缓存 SQL 不带 `content_hash`，只按 url+lang 取最新一条并在 JS 里比对 hash。主库只要存在一条 stale / 空 hash / 损坏记录就短路，DB999 的有效缓存永远读不到（实测 200 变 410）。另一个问题：命中备用库后 `renderCachedTranslationHtml` 的 CSS 快照回写用 failover 包装器的 `run()`，固定落主库，会用 DB999 的 id 覆盖 SW998 同号记录。

**改法**：
- 新增 `readPageTranslationCandidates()`：逐库 `all()` 取最近 10 行，hash 条件下推到 SQL，按 created_at 合并且返回每行的真实库绑定。
- `createD1FailoverDatabase` 记录 `lastReadDb`，`run()` 改为「读哪库写哪库」，暴露 `getLastReadDb()`；`renderCachedTranslationHtml` 内部解包。
- `lib/app.ts` 新增 `pickPageCacheHit()`，三处缓存查询（check / POST / translate-url-page）统一走跨库挑选；保留 410 stale 语义、空 hash 视为未命中、不健康行跳过。
- `wrangler.toml` 注释补上读写顺序的区别。

**验证**：`tsc --noEmit` 干净；`npm test` 73 文件 / 857 项全通过。新增 12 项测试（pageStore 6、appRoutes 6），`tests/translateUrlRoute.test.ts` 的 stale mock 补了 `all()` + content_hash 返回。

**注意**：`createMockDb`（appRoutes.test.ts）的 `all()` 不按 url/lang 过滤，双库用例每库只放一行；这是测试替身限制，不是实现问题。
