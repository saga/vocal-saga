## 第十一批：补齐 local-agent-service 全部顶层声明注释（71.2% → 100%）

用 TypeScript compiler API 扫描 `src/**/*.ts`，统计「函数 / 类 / 接口 / 类型别名 / 导出常量」
这五类顶层声明的注释覆盖。起点 871 个声明里 221 个完全没有说明（25.4%），三个提交后归零。

**扫描器的坑**：第一版只把 `/** */` 算作已注释，于是把 `//` 行注释的声明也计入缺口，
报出 251 个（28.8%），实际是 221 个。判定要同时接受两种注释形式。

**写法原则**：只记「读代码看不出来的部分」。四类值得写：
1. **不变量与协议** —— 如 `segmentHash` 的字段顺序即协议，改顺序让已存指纹全量失效；
   `BOOK_SCAN_INDEX_VERSION` 必须在词表变化时递增，否则旧索引被误判可复用。
2. **反直觉的取舍** —— 如 `collectEntityMentions` 实际不做重叠抑制（长名与其中短名各成一条），
   `validateSegments` 畸形项跳过但重复 id 报错，`decodeText` 失败直接 415 而不猜字符集。
3. **数值的由来** —— 单引号 `quoteSpans` 要 8 字符门槛（撇号误命中）、
   重复表达要 12 字符/3 实词（否则口头禅淹没真意象）、虚拟分段 40 块或 2 万字符。
4. **易误用的语义** —— `BookNameCandidate.score` 是覆盖率排序分不是置信度（写出公式各项权重）。

反之，`HOST`/`sleep`/`isoNow` 这类自解释的只给一行。

**顺带修的三类既有问题**（都是加注释时暴露的）：
- 同一函数上叠了多段 `/** */`（bookScan 的并发/同步/抽样三处、ingest 的 EPUB/PDF 两处）——
  历史增量注释叠加所致，合并成一段并保留信息量更大的表述。
- 注释与声明错配：`translationRun` 里「Run 级工作流协调器」那段挂在 `prepareRunExecution` 上，
  实际属于 `executeRun`；`contextGraphSchema` 里系统提示词的注释压在版本号常量上。
- 注释被误替换：给 `extractPdfText` 加注释时覆盖掉了原有那句「通过 pdftotext 提取文本层」，
  该实现细节必须保留，合并回来了。
